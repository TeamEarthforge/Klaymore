# Klaymore 脚本项目生成器 - 使用教程

> 本工具会自动生成一个**专供编写 Klaymore 脚本**的独立 Gradle 项目：
> - **开发时（IDE 里）**用 **`.kt`** 后缀 = 标准 Kotlin 源文件，**100% 继承项目 compileClasspath**（Minecraft/Forge 类全在 External Libraries，代码补全/类型检查/跳转完美）
> - **部署到服务端时**用 **`.kts`** 后缀 = Klaymore 运行时格式，把 `.kt` **复制一份改后缀为 .kts**，拷到服务端即可
>
> 写好的脚本只需复制到服务端 `scripts/` 目录即可运行。

---

## 📦 生成器包含的文件

| 文件名 | 用途 | 需要改吗 |
|--------|------|----------|
| `config.properties` | **唯一配置文件**（填 JAR 路径） | ✅ **需要改** |
| `generate.bat` | Windows 启动（双击运行） | ❌ 不用 |
| `generate.sh` | Linux / macOS 启动（`./generate.sh`） | ❌ 不用 |
| `generate_project.py` | 生成器核心代码（Python 3.7+） | ❌ 不用 |

生成过程中还会输出：
- `generated-project/` → 生成的 Gradle 脚本开发项目
- `klaymore-scripts.zip` → 同上，打包成 zip（加 `--zip` 参数时生成）

## 🚀 3 步快速上手

### 第 1 步：编辑 `config.properties`

用记事本 / VS Code / IDEA 打开 `config.properties`，这是你**唯一需要改**的文件。

最关键的是填好 **Klaymore Mod JAR 路径**（必填）：

```properties
# --------------------
# 3. Klaymore Mod JAR 路径【必须填写】
# --------------------
# 填 Klaymore 构建产物里的 *-dev.jar（已反混淆的开发版）
#
# Windows 示例：
klaymoreJar=F:/MCRPG/Klaymore/build/libs/klaymore-1.0.0-dev.jar
#
# Linux / macOS 示例：
#klaymoreJar=/home/user/Klaymore/build/libs/klaymore-1.0.0-dev.jar
```

> 💡 **怎么找这个 JAR？**
> 从github下载Klaymore的dev版本。

---

### 第 2 步：添加其他 Mod JAR（可选）

如果你的脚本里要用到其他 Mod（例如 IC2、GregTech、NEI、ProjectE 等），
需要把那些 Mod 的 JAR 路径也告诉生成器，否则 IDE 里引用它们的类会报红。

**两种写法任选（可同时用，会合并去重）：**

```properties
# 写法 A：一行写多个，用英文逗号分隔
extraJars=F:/mods/IC2.jar,F:/mods/GregTech-api.jar,F:/mods/NEI.jar

# 写法 B：编号多行（推荐，更清晰，想写多少个就 extraJar.1 ~ extraJar.N）
extraJar.1=F:/mods/IC2.jar
extraJar.2=F:/mods/GregTech-api.jar
extraJar.3=F:/mods/NEI.jar
extraJar.4=F:/mods/ProjectE-api.jar
```

> 💡 **不想改配置？** 更简单的做法：
> **先完成第 3 步生成项目**，然后把需要的 JAR 直接拖进生成项目的 `libs/` 文件夹，
> IDEA 重新同步 Gradle 后一样会识别（`libs/*.jar` 自动用 `rfg.deobf` 包裹）。

---

### 第 3 步：运行生成器

| 系统 | 运行方式 |
|------|----------|
| **Windows** | 双击 `generate.bat` |
| **PowerShell** | `.\generate.bat` 或 `python generate_project.py` |
| **Linux / macOS** | `chmod +x generate.sh && ./generate.sh` |
| **任意** | `python generate_project.py`（需 Python 3.7+）|
| **额外打包 ZIP** | `python generate_project.py --zip` |

看到 `[成功] 项目生成完成!` 就 OK 了。

> 💡 如果输出目录已经存在，生成器会**自动备份**（重命名为 `generated-project_backup_时间戳/`），不会覆盖你的已有工作。

---

## 💻 第 4 步：在 IDEA 中打开并写脚本

### 4.1 打开项目（正确姿势，别用 Import Project）
1. **先关闭 IDEA 里旧的 generated-project 窗口**（如果之前打开过，防止 `.idea/` 缓存干扰）
2. 打开 **IntelliJ IDEA**（社区版或旗舰版都行，一定要装 Kotlin 插件——默认已预装）
3. `File → Open…`（**不要用 Import Project**，新版 IDEA 原生支持 Gradle）
4. 选中生成器输出的 **`generated-project/` 文件夹本身**（不是里面的 build.gradle.kts 文件）→ OK
5. 右下角弹提示：
   - 先点 **Trust Project**（信任 Gradle 项目，否则不加载依赖）
   - 再点 **Load Gradle Project**

> 💡 **推荐更干净的方式**：解压 `klaymore-scripts.zip` 到一个完全独立的目录（比如 `D:\klaymore-scripts-workspace\`）再 Open，避免旧缓存污染。

### 4.2 等待同步（第一次慢一点是正常的）
IDEA 会自动做下面这些事（右下角进度条可看）：
1. 下载 Gradle 9.3 Wrapper（~120MB，一次性缓存在 `~/.gradle/wrapper/`）
2. 按 `gradle.properties` 自动下载 **JDK 25**（只给 Gradle 守护进程用，不影响系统 JAVA_HOME，约 200MB）
3. RetroFuturaGradle 下载 Minecraft 1.7.10 / Forge 10.13.4.1614 / MCP stable-12 映射
4. 把你配置的 Klaymore JAR + 所有 extraJar 执行 `rfg.deobf`（混淆→可读类名）
5. IDEA 对所有外部 JAR 建立索引 → 代码补全、类型检查上线 ✨

同步成功标志：右侧 **Gradle 面板**（没有的话 View → Tool Windows → Gradle）里项目名左边显示**绿色小勾** ✅。

### 4.3 ★ 关键：确认「外部库里确实出现 Minecraft/Forge 类」（两种方法）
同步完**先别急着写脚本**，用下面两种方法确认环境真的 OK（这一步能帮你 99% 排除配置错误）：

#### 方法 A：看左侧 External Libraries 树
左侧 `Project` 面板（按 `Alt+1` 调出），视图下拉切到 **「Project」**（不是 Packages/Android），向下滚动找到 **External Libraries** 节点，展开能看到：
```
External Libraries
  ├── Gradle: org.jetbrains.kotlin:kotlin-stdlib:2.2.21   （Kotlin 标准库）
  ├── Gradle: minecraft 1.7.10 patched deobf + 50 artifacts  ← ★ Minecraft 类
  │     └── net.minecraft / net.minecraftforge           ← 点进去能打开 ItemStack.class 等
  ├── Gradle: forge-1.7.10-10.13.4.1614-universal.jar    ← ★ Forge API
  │     └── cpw.mods.fml.common.MinecraftForge            ← EVENT_BUS 能跳转
  ├── Gradle: klaymore-xxx-dev.jar (rfg.deobf)            ← ★ Klaymore API
  │     └── com.earthforge.klaymore.api.*                 ← @Subscribe 注解
  └── （你配置的 extraJar + libs/*.jar 也都在这里）
```
**看到 `Gradle: minecraft … patched` 那一项 → Minecraft 类已经在 classpath 了 ✅**

#### 方法 B：打开 ExampleScript.kt 看有没有红色
打开 `src/main/kotlin/ExampleScript.kt`，**任何 import / 类名不红** = 环境完美：
- ✅ `import net.minecraft.item.ItemStack` → Ctrl+B 能点进去看源码 → 正确
- ✅ `import cpw.mods.fml.common.MinecraftForge` → `MinecraftForge.EVENT_BUS.register(...)` 有补全 → 正确
- ✅ `@com.earthforge.klaymore.api.annotation.Subscribe` → 注解不红 → 正确
- ❌ 只要有一个红色 Unresolved reference → 看下面「4.4 两步快速排坑」和「4.6 强制清缓存 6 步」

### 4.4 两步快速排坑（90% 的初始化问题是这俩）
#### ❌ 坑 1：External Libraries 空 / Gradle 面板没绿勾
**根因**：没点 Load Gradle Project / IDEA Gradle JVM 选了本地 JDK 8/17/21（RFG 2.0.2 需要 JDK 25 运行）。
**修**：
1. 右侧 Gradle 面板 → 点左上角 🔄 **Reload All Gradle Projects** 按钮。
2. 如果还报错 → `File → Settings → Build, Execution, Deployment → Build Tools → Gradle`：
   - **Gradle JVM** 下拉 → 选 **Download JDK…** → 版本选 **Eclipse Temurin 25 (LTS)** → Download
   - 选完 Apply → OK → 再次 Reload Gradle

#### ❌ 坑 2：net.minecraft / cpw.mods.fml 红（但 Kotlin 不红）
**根因**：Gradle 同步时 RFG 下载 / 解析 Minecraft/Forge 中途失败，导致 3 个 MC 配置里没挂到 classpath。
**修**：
1. 打开 IDEA 底部 **Build 面板**（`Alt+0`）→ 看有没有红色错误：
   - 网络错误 → 配 Gradle 代理 / 切手机热点再 Reload
   - `Unresolved dependency net.minecraft:forge` → 检查 `gradle.properties` 的 `minecraftVersion` + `forgeVersion` 是否对应你服务端版本
2. 最简单的终极手段：**强制清缓存 6 步**（见下面 4.6）

### 4.5 开始写脚本
- 脚本放 `src/main/kotlin/` 下（可以新建子目录 / 子包）
- **⚠️ 文件扩展名必须是 `.kt`（不是 .kts！）**：
  - ✅ `.kt` = 标准 Kotlin 源文件，**100% 继承项目 compileClasspath**，Minecraft/Forge/Klaymore 类全能找到，代码补全/类型检查/跳转全正常
  - ❌ `.kts` = Kotlin Script 模式，默认 classpath **不继承**项目 dependencies，会导致 Minecraft/Forge 类全红、IDE 吃不到依赖
- 项目里自带两个模板可直接参考：
  - `ExampleScript.kt` - 完整示例（@Subscribe 事件、数据存储、公共方法调用、give 物品、发送消息等）
  - `MyScriptTemplate.kt` - 极简空白模板，复制 → 改文件名即可开写
- **拷到服务端前改名**：把 `.kt` 复制一份 → **手动改扩展名为 .kts**（Klaymore 运行时加载格式）

### 4.6 ★ 强制清缓存 6 步（External Libraries 没有 Minecraft / 类一直红终极手段）
如果 Gradle 面板绿勾了，但 External Libraries 里仍然**没有 `minecraft patched` 那一项**（只有 Forge / Kotlin，没有 Minecraft），这是 IDEA Gradle Tooling API 缓存污染，按顺序做：
1. **关闭 IDEA**（必须完全关掉，右下角 Gradle daemon 也要停）
2. **打开生成项目根目录**，删除下面 3 个目录/文件（全是缓存，删了无害，.gitignore 已包含它们）：
   ```
   .idea/          ← IDEA 项目配置 + Workspace Model 缓存
   .gradle/        ← Gradle 配置缓存 + configuration-cache
   build/          ← 编译产物
   ```
3. **打开命令行**（PowerShell / CMD），进入项目根目录，运行：
   - Windows：`gradlew.bat --stop`
   - 这会杀掉所有旧 Gradle 守护进程（包括 JDK21 启动的"毒 daemon"）
4. **重新打开 IDEA** → File → Open → 选中项目目录 → Trust Project → **Load Gradle Project**
5. 等 Gradle 同步跑完（右下角 `indexing...` 和 Gradle 进度条都结束），**再等 30s**（IDEA 有时候要等 Configuration Cache 写入完成后才把新 JAR 挂到 External Libraries）
6. 再去看 **External Libraries**，现在 `Gradle: minecraft 1.7.10 patched deobf + 50 artifacts` 这一项 100% 会出现。
   - 如果还没有 → 右侧 Gradle 面板 → 🔄 Reload All Gradle Projects，再等 1 分钟

---

## 🚢 第 5 步：把脚本部署到服务端

写好脚本后，只有一步：**复制 + 改后缀名**。

```
src/main/kotlin/xxx.kt    ← IDE 里写脚本时用（.kt 后缀吃完整 compileClasspath）
           ↓ 复制一份，把扩展名 .kt 改成 .kts
服务端 scripts/xxx.kts    ← Klaymore 服务端只认 .kts
```

### 最终拷到服务端
把 `.kts` 文件复制到你服务端的 Klaymore 脚本目录（通常是：
`服务端根目录/mods/Klaymore/scripts/`，具体请查阅 Klaymore Mod 文档）。

服务端使用 **Klaymore 的命令**（一般是类似 `/klaymore reload`，请以 Klaymore 实际命令为准）
即可热重载脚本，不用重启服务器。

## ⚙️ 配置文件完整字段说明

`config.properties` 里所有可改项：

### 1. 项目基本信息（一般不用改）
| Key | 说明 | 默认 |
|-----|------|------|
| `projectName` | 生成项目的名称 / Gradle rootProject.name | `klaymore-scripts` |
| `outputDir` | 生成项目的输出目录（相对路径相对生成器所在目录） | `generated-project` |
| `modGroup` | Gradle `group`（Maven 坐标用） | `com.earthforge.klaymore` |
| `scriptApiPackage` | Klaymore 注解 API 包（import `@Subscribe` 用的包） | `com.earthforge.klaymore.script` |

### 2. 版本信息（必须与服务端**完全一致**）
| Key | 说明 | 默认 |
|-----|------|------|
| `minecraftVersion` | Minecraft 版本 | `1.7.10` |
| `forgeVersion` | Forge 版本号（仅数字，不含 MC 前缀） | `10.13.4.1614` |
| `mappingsChannel` | MCP Mapping 通道（stable / snapshot / nightly） | `stable` |
| `mappingsVersion` | MCP Mapping 版本 | `12` |
| `kotlinVersion` | Kotlin 插件和 stdlib 版本 | `1.9.22` |

> ⚠️ **版本不一致会导致**：IDE 里补全正常 → 拷到服务端运行时类找不到 / 字段方法对不上。

### 3. JAR 路径
| Key | 必选 | 说明 |
|-----|------|------|
| `klaymoreJar` | ✅ 必须 | Klaymore Mod 的 `-dev.jar`（提供 `@Subscribe` 注解 + 脚本运行时 API） |
| `extraJars` | ⬜ 可选 | 逗号分隔的额外 Mod JAR 列表 |
| `extraJar.N` | ⬜ 可选 | 编号多行（N=1,2,3…）额外 Mod JAR，顺序和数量不限 |
| `minecraftDevJar` | ⬜ 可选 | 已反混淆 Minecraft JAR（GTNH 插件会自动配置，一般不用填） |
| `forgeJar` | ⬜ 可选 | Forge JAR（同上，通常不填） |

## ❓ FAQ / 常见问题

### Q1：打开项目后，所有 Minecraft / Forge 类都是红色？
1. 等 Gradle 同步完成（右下角进度条 / 右侧 Gradle 面板绿色勾）
2. 确认 IDEA 里 **Gradle JVM 选了 JDK 25**：`File → Settings → Build Tools → Gradle → Gradle JVM = 25`（RFG 2.0.2 需要 JDK25 才能加载插件）
3. **Project SDK 设 JDK 1.8**：`File → Project Structure → Project → SDK = 1.8`（脚本编译输出依然是 JDK8 字节码，兼容服务端）
4. `File → Invalidate Caches... → 全勾 → Invalidate and Restart`
5. 还是红 → 直接走上面「**4.6 强制清缓存 6 步**」（95% 的问题是 IDEA Workspace 缓存污染）

### Q2：`@Subscribe` 注解是红色？
→ `klaymoreJar` 路径不对：
   1. 检查 JAR 是否真实存在（生成器会警告路径不存在）
   2. 要用 **`*-dev.jar`**（开发版、已反混淆），不是服务器运行的发行版 JAR
   3. 改完路径重新运行生成器

### Q3：我引用了 IC2 / GregTech 的类，IDE 报红但服务端能用？
→ 这是因为 IDE classpath 里没加那个 Mod JAR。解决三选一：
   - 在 `config.properties` 加 `extraJar.N=路径` → 重新生成
   - 直接把 Mod JAR 复制到生成项目的 `libs/` 目录 → 刷新 Gradle
   - 手动在 `build.gradle.kts` 里加 `rfg.deobf(files("路径"))` → 刷新 Gradle

### Q4：JAR 路径里有空格 / 中文 / 特殊字符可以吗？
可以，**不要加引号**，直接写即可：
```properties
extraJar.1=C:/My Mods/格雷科技/GregTech-api.jar
```

### Q5：Windows 路径应该用 `\` 还是 `/`？
两种都可以：
```properties
klaymoreJar=F:/MCRPG/Klaymore/build/libs/klaymore-dev.jar     # 推荐（正斜杠）
klaymoreJar=F:\\MCRPG\\Klaymore\\build\\libs\\klaymore-dev.jar # 双反斜杠也 OK
```

### Q6：生成器报 "未找到 Python 环境"？
去 [Python 官网](https://www.python.org/downloads/) 安装 Python 3.7+，
**安装时一定要勾选** `Add Python to PATH`。装完重新开一个命令行窗口。

### Q7：IDEA 导入后，Gradle 面板显示 GTNH 插件下载失败？
网络（被墙 / 公司代理）连不上 `nexus.gtnewhorizons.com` 或 `services.gradle.org`：
- 配置 IDEA 的 Gradle 代理（Settings → Build → Gradle）
- 或用手机热点 / 游戏加速器

## 🧠 架构说明：为什么新版更"简洁"也更稳？

旧版生成器为了复用 `gtnhconvention` 插件，把**整套 Mod 开发模板**都带进来了，导致 IDEA 里生成很多脚本项目根本不需要的东西（`patchedMc` / `forge` / `minecraft` 三个子模块、Minecraft Dev 插件 Facet、Run Config 等），这些就是你遇到 `Storage inconsistency. Hard reference broken. FacetEntityData(...patchedMc...)` 报错的**根因**。

**新版生成器（2026-08-29 后）架构=极简三件套**：
```
┌─────────────────────────────────────────────────────────────┐
│ build.gradle.kts                                            │
│   plugins {                                                 │
│     id("com.gtnewhorizons.retrofuturagradle") version("2.0.2")  ← 只加它自己，提供 rfg.deobf
│     kotlin("jvm") version("2.2.21")                         ← Kotlin 语法
│     idea                                                    ← IDEA 源码根标记
│   }                                                         │
│   dependencies {                                            │
│     // ★ 根因修复：不使用 extendsFrom（IDEA Tooling API 不识别）
│     //    直接把 patchedMinecraft/forgeUniversal/vanilla_minecraft
│     //    3 个 configuration 转成显式 files(...) 挂到 implementation
│     //    → 配置阶段 + projectsEvaluated 双保险，IDEA 一定能看到 MC 类
│   }                                                         │
│   // 没有：gtnhconvention！没有：settingsconvention！       │
└─────────────────────────────────────────────────────────────┘
```

✅ **去掉 gtnhconvention 之后：**
- 没有 `patchedMc` / `forge` / `minecraft` 这些额外子模块 → IDEA 不会挂 Minecraft Facet → 不会再出现 Storage Inconsistency
- 不再强制需要 `blowdryerTag`、`modGroup 占位目录`、`apiPackage / coreModClass` 等一堆 GTNH 插件校验属性
- Gradle `Configure 阶段` 速度更快（GTNH convention 要跑几十条 Mod 开发检查，现在全部跳过）

❌ **但 RFG 2.0.2 插件本身需要 JDK 25 才能运行**（它是用 Java 25 编译的 class file 69.0）：新版生成器在 `gradle.properties` 里用 `org.gradle.daemon.jvm.version = 25` 让 Gradle 自动 provision JDK 25，**完全不需要你手动装 / 手动设 JAVA_HOME**。

## ❓ FAQ 常见问题

### Q1：为什么 IDE 里脚本后缀用 .kt，拷到服务端又要改回 .kts？
这是**刻意的两种后缀分工**，目的就是解决你之前".kts 吃不到依赖"的痛点：

| 后缀 | 阶段 | classpath 行为 |
|------|------|---------------|
| `.kt` | **开发时（IDE）** | 标准 Kotlin 源文件，**自动继承整个项目的 `compileClasspath`** ✅ → Minecraft/Forge/Klaymore 类 100% 可见，补全/类型检查全正常 |
| `.kts` | **服务端运行时** | Kotlin Script，由 Klaymore 引擎直接解释执行，用自己的脚本 classpath（不是 Gradle compileClasspath）|

**部署时改名**：把 `src/main/kotlin/**/*.kt` **复制一份**，手动改扩展名 `.kt → .kts`，拷到服务端即可。

### Q2：IDEA 打开后 `.kt` 文件里面全是红色「Unresolved reference」？
99% 是 IDEA 没识别 `src/main/kotlin` 作为源码根 或 Gradle 同步失败：
1. 先看右侧 Gradle 面板有没有**绿色勾**（没勾=Gradle 同步没成功，绿勾之前任何红色都没意义）
2. 有绿勾还是红 → 右侧 Gradle 面板 → 右键项目 → **Reload Gradle Project**
3. 等 IDEA 右下角索引进度条跑完（第一次要 30s~3 分钟）
4. 如果还是红色：`File → Project Structure → Modules → Sources`，手动把 `src/main/kotlin` 点成蓝色「Sources」图标
5. 终极：走「**4.6 强制清缓存 6 步**」（解决 IDEA Workspace 缓存污染，External Libraries 里没 Minecraft 的问题）

### Q3：`config.properties` 里填了 JAR 路径，重新生成项目后 IDE 还是没生效？
生成器会**自动备份**旧的 `generated-project/`（时间戳命名），所以每次重新生成是**新目录**，IDEA 不会自动刷新。你需要：
- 把 IDEA 窗口里的项目**关掉再重新 Open** 新的 `generated-project/` 目录，**或者**
- 直接解压生成的 `klaymore-scripts.zip` 到任意目录再 Open（更干净）

### Q4：Kotlin 版本报错？想要用别的 Kotlin？
- 建议直接用生成器默认的 **Kotlin 2.2.21**（和 Klaymore 主项目同步）
- 想改：在 `config.properties` 里加一行 `kotlinVersion=1.9.24` 然后重新生成即可
- 注意：你写的脚本运行时**只能用服务端 Klaymore 自带的 Kotlin 版本**，版本不匹配会有运行时警告

### Q5：为什么 Gradle 同步特别慢？第一次同步一直在下载？
正常！第一次同步需要下载（都是一次性下载缓存到 `~/.gradle/caches/`）：
- Gradle 9.3 本身（~150MB）
- JDK 25（仅守护进程用，~200MB）
- MCP stable-12 映射文件（~50MB）
- Kotlin Gradle 插件 + 依赖（~100MB）

**加速建议：**
- 配置 IDEA 的 Gradle 代理（Settings → Build → Gradle）
- 或用手机热点 / 游戏加速器
- JDK 25 下载慢：启用下面的清华镜像（加到 gradle.properties）
  ```properties
  org.gradle.jvm.toolchain.download.base-url = https://mirrors.tuna.tsinghua.edu.cn/Adoptium/
  ```

### Q6：我没有 JDK 25，也不想下载 JDK 25，能跑吗？
不行。RFG 2.0.2 插件本身就是用 JDK 25 字节码编译的（这是 GTNH 生态的硬性版本要求），没有 JDK 25 它根本加载不起来。

但你**不用手动装**！新版生成项目在 `gradle.properties` 里写了：
```properties
org.gradle.daemon.jvm.version = 25
org.gradle.java.installations.auto-download = true
```
Gradle 会自动从 Adoptium 下载 JDK 25 到 `~/.gradle/jdks/`，不会影响系统 JAVA_HOME、不会污染其他项目。等它下载完就 OK 了。

### Q7：我想自己调依赖声明（比如加 Maven 库）？
直接改生成项目的 `build.gradle.kts` 里的 `dependencies {}` 和 `repositories {}` 就行，生成器只负责「生成一个可以工作的起始项目」，后续你可以自由改造。

### Q8：gradle.properties 里 `org.gradle.daemon.jvm.version=25` 会让我的脚本字节码变成 JDK 25 吗？
**不会！** 它**只影响 Gradle 守护进程**（也就是运行 Gradle/RFG 插件的那个 JVM）。脚本实际编译走的是 `kotlin { jvmToolchain(8) }` + `java { sourceCompatibility = 1.8 }`，**编译输出依然是 JDK 8 字节码**，可以直接丢到 1.7.10 服务端上运行。

### Q9：旧版生成器遇到过的报错对照（新版已全部解决）
下面这些是旧版生成器（使用 `gtnhconvention` / `settingsconvention`）的常见坑，**新版生成器已经彻底移除 gtnhconvention，所以基本都不会再遇到**。但如果你用的是旧项目，这里给出对应原因 + 修复方式：

| 错误 | 根因 | 新版如何解决 |
|------|------|--------------|
| `Plugin [id: 'com.gtnewhorizons.gtnhconvention'] was not found` | settings.gradle.kts 缺少 gtnhsettingsconvention 插件声明（两阶段架构） | 彻底移除 gtnhconvention 插件，直接在 build.gradle.kts 里用 `id("...retrofuturagradle") version("2.0.2")` |
| `Dependency requires at least JVM runtime version 25` | GTNH Settings Convention 2.0.20 需要 JDK25 daemon | 仍然需要 JDK25（RFG 2.0.2 也需要），但通过 `org.gradle.daemon.jvm.version=25` 自动 provision |
| `Could not resolve "modGroup"! Could not find src/main/java/.../klaymore` | GTNH Convention 严格检查 modGroup 包目录 | 移除 gtnhconvention 后**不再有此检查** |
| `Script compilation error: kotlinOptions is deprecated` / `testSourceDirs unresolved` | 旧版 Gradle/IDEA DSL 被 Kotlin 2.2 升级移除 | 新版 build.gradle.kts 已经全面迁移到 `compilerOptions {}` 新 DSL、移除无效属性 |
| **`Storage inconsistency. Hard reference broken`（FacetEntityData / patchedMc / MinecraftFacetConfigurationData）** | **GTNH Convention 自动创建 `patchedMc`、`forge` 等附加子模块，且 IDEA 给它们挂 Minecraft Facet，Workspace Model 在模块引用断裂时崩溃** | **✅ 核心修复：彻底移除 gtnhconvention，直接用 RFG 底层插件 → 不再生成那些子模块 → 不再挂 Facet → 不会有引用断裂**（见上面「架构说明」小节）|
| **「Forge 有但 Minecraft 没有」—— External Libraries 里只有 forge-universal，没有 minecraft patched** | **使用 `configurations.implementation.extendsFrom(patchedMinecraft)` 方式：IDEA Gradle Tooling API 只能识别 Maven 坐标 + 直接 files(...)，不识别 configuration extends 关系，所以 3 个 MC configuration 里的 JAR 没被 IDEA 收集** | ✅ **改成「配置阶段 + projectsEvaluated 兜底」双重显式 `dependencies.add("implementation", project.files(cfg))`** → IDEA Tooling API 100% 能把 patchedMinecraft JAR 放进 External Libraries |

### Q10：还是出现 IDEA `Storage inconsistency / Hard reference broken` 怎么办？
这是 IDEA Workspace Model 的**本地缓存损坏**问题（不一定是 Gradle 项目的锅）。新版生成器已经从根因上消灭了 patchedMc/Facet 相关的断裂，但仍可能因为 IDEA 崩溃、杀进程、断电等出现。**标准修复流程**（.gitignore 里已经把 .idea/ 设为可删除）：
1. 关闭 IDEA
2. 到项目根目录把这几个**本地文件/目录删掉**（它们都是 IDEA 本地缓存，丢失无害）：
   ```
   .idea/
   *.iml
   .gradle/
   ```
3. 重新打开 IDEA → Open → 选中项目目录 → Load Gradle Project
4. （可选）如果还是不行，`File → Invalidate Caches... → 勾选所有 → Invalidate and Restart`

### Q11：生成项目里的 `libs/` 目录是干嘛的？
`libs/` 是**快速依赖目录**：你不需要改 `config.properties`，直接把 Mod JAR 文件（IC2.jar、GregTech-api.jar 之类）丢进去，`build.gradle.kts` 会自动用 `implementation(files(...))` + `rfg.deobf(fileTree(...))` 双份引用，IDE 立即识别类 + 自动反混淆混淆 JAR。

## 🧩 生成的项目中 `rfg.deobf` 做了什么？

RetroFuturaGradle（我们现在直接用的底层插件）提供了 `rfg.deobf(...)` 扩展：
对传入的混淆 JAR（例如服务端 mods/ 里从 CurseForge 下载的原版 Mod JAR），
**按 MCP Mapping 自动反混淆类名/字段名/方法名**，然后再加入 classpath。

这意味着：
- ✅ 即使你给的是**原始混淆版 JAR**，IDE 里也能看到 `EntityPlayer`、`ItemStack`
  这些可读名字（而不是 `aab`、`awe` 之类的混淆名）
- ✅ 代码补全 / 跳转 / 错误检查全部正常工作
- ✅ 这也是 GTNH 生态所有 Mod 项目的标准做法

生成器里三个地方都用了它：
```kotlin
// 1) Klaymore JAR
rfg.deobf(files("F:/MCRPG/Klaymore/build/libs/klaymore-xxx-dev.jar"))

// 2) 配置中所有 extraJar
rfg.deobf(files("F:/mods/IC2.jar"))
rfg.deobf(files("F:/mods/GregTech-api.jar"))

// 3) libs/ 目录全部 JAR（拖进来就生效）
rfg.deobf(fileTree("libs") { include("*.jar") })
```

## 📝 小提示

- **.kt vs .kts 分工（⭐⭐⭐ 最容易踩的坑）**：
  - IDE 里写脚本 → 用 **`.kt`**（标准 Kotlin 源文件，吃完整 compileClasspath）
  - 拷到服务端运行 → 用 **`.kts`**（Klaymore 只加载这个）
  - 复制一份 `.kt` 手动改后缀为 `.kts` 即可，IDE 里的 `.kt` 原文件保留继续开发
- **想调试脚本逻辑**：直接在 IDEA 里写一个 `main()` 或 `@Test` 调用脚本里的函数（纯逻辑部分）
- **版本变更**：升级服务端 MC/Forge 版本 → 在 `config.properties` 改版本号 → 重新生成
- **保留自定义**：如果手动改了生成项目的 `build.gradle.kts`，下次重新生成前记得备份！
